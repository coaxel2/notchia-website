Notes de version · 2.9.20

Homing Pigeon : ce qui ne marchait pas le dit enfin

Par NotchIA · 27 août 2026 · 3 min de lecture

Trois corrections qui partagent le même défaut : une fonction s'arrêtait de marcher sans jamais le signaler. Le pire mode de panne, parce qu'on ne le cherche pas.

Vos sessions Claude Code étaient peut-être invisibles

Quand vous déplacez ou renommez le dossier d'un projet, Claude Code laisse derrière lui un lien symbolique de l'ancien emplacement vers le nouveau. NotchIA ne traversait pas ces liens.

Conséquence : toutes les sessions des projets déplacés disparaissaient du suivi. Pas de chrono, pas d'activité en direct, pas de notification en fin de tour. Rien n'indiquait que quelque chose manquait, l'encoche restait simplement muette.

Sur la machine de test, trois projets sur quatre étaient silencieux depuis une réorganisation de dossiers. Si vous avez rangé vos projets récemment et trouvé NotchIA étrangement calme, c'était ça.

Les notifications sont enfin cliquables

Il manquait à l'app le composant qui reçoit les clics sur les notifications. Deux effets, l'un visible, l'autre plus sournois :

  • Cliquer sur une notification ne faisait rien du tout.
  • macOS supprimait purement et simplement les notifications quand NotchIA était l'app au premier plan. Pour une app d'encoche, c'est-à-dire toujours là, ça arrivait souvent.

Désormais, un clic sur « Claude a terminé » ramène au premier plan le terminal ou l'IDE de la session concernée. Un clic sur une alerte d'autorisation ouvre directement le bon volet des Réglages système.

Une alerte quand il manque une autorisation

Une fonction privée de son autorisation macOS ne proteste pas : elle ne fait rien. NotchIA surveille maintenant les autorisations dont dépendent les fonctions que vous avez activées, et vous prévient avec un lien direct vers le volet concerné.

Deux garde-fous pour que ça reste discret : rien n'est signalé pour une fonction que vous avez désactivée, et un même manque n'est rappelé qu'une fois par semaine.

Cas amusant : impossible de notifier qu'il manque l'autorisation de notifier. Celui-là est affiché en tête de l'écran d'audit des autorisations.

Sous le capot

Le lien direct vers les réglages de notifications utilisait un identifiant abandonné par macOS 13, quand ce panneau a changé de nature. Il n'ouvrait plus rien. Les quatre liens de réglages ont été revérifiés un par un.

Questions fréquentes

Pourquoi NotchIA ne suivait plus mes sessions Claude Code ?

Si le dossier du projet a été déplacé ou renommé, Claude Code laisse un lien symbolique de l'ancien emplacement vers le nouveau. NotchIA ne traversait pas ces liens : les sessions de ces projets devenaient invisibles, sans chrono ni notification de fin de tour. La 2.9.20 les suit correctement.

Que se passe-t-il quand on clique une notification NotchIA ?

Un clic sur « Claude a terminé » ramène au premier plan le terminal ou l'IDE de la session concernée. Un clic sur une alerte d'autorisation ouvre directement le volet correspondant des Réglages système. Avant cette version, cliquer une notification ne faisait rien.

Comment savoir si une autorisation macOS manque à NotchIA ?

NotchIA surveille les autorisations dont dépendent les fonctions que vous avez activées et vous prévient avec un lien direct vers le bon volet des Réglages système. Rien n'est signalé pour une fonction désactivée, et un même manque n'est rappelé qu'une fois par semaine.

Comment l'obtenir

Déjà utilisateur ? L'auto-update Sparkle vous propose la 2.9.20 automatiquement. Pour forcer : menu NotchIA → Vérifier les mises à jour.

Nouvel utilisateur ? brew install --cask coaxel2/notchia/notchia, ou le .dmg depuis la page d'installation.
